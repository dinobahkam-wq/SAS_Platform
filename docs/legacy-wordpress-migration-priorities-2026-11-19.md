# ترحيل أرشيف ساس القديم — الأولويات وسجل المصدر

**التاريخ:** 19 نوفمبر 2026  
**المصدر:** https://www.sas-media.net/  
**المستهدف:** منصة ساس الجديدة (Next.js + Supabase)، نظام `content_items`.  
**الحالة:** أداة الاستيراد جاهزة ضمن فرع `feat/legacy-wordpress-migration-v1`، لكن **لا توجد مادة نُقلت إلى قاعدة البيانات عبر هذه الأداة بعد**؛ تعذّر جلب النصوص الأصلية آليًا من WordPress. لا ننشر مقتطفًا بوصفه المقال الكامل.

## نتيجة الجرد التقني

- WordPress متصل بحساب المستخدم ويعرّف الموقع بمعرف `244649364` واسمه «منصة ساس للإعلام والدراسات».
- `wpcom_mcp_posts_list`، `wpcom_mcp_pages_list`، `wpcom_mcp_categories_list` و`wpcom_mcp_media_list` أعادت `404` بدل البيانات.
- بحث `wpcom_mcp_site_posts_search` أعاد `found_posts=0` رغم أن صفحات الأرشيف ظاهرة للزائر، بما يرجح خلل الربط/API أو اختلاف بنية نشر الموقع؛ لا يُستنتج منه أن الموقع بلا محتوى.
- فُحصت قاعدة Supabase المستهدفة: `content_items` يحتوي 20 سجلًا عند الجرد، بينها ست مواد تحليل/رأي تجريبية مؤرشفة مسبقًا، ولا ينبغي نشرها بوصفها أصول WordPress أو تكرارها.
- صفحات الأرشيف القديمة يمكن فهرستها علنًا، لكنها لا تكفي لاستخراج النص الكامل ومؤلفه وصوره وحقوق الاستخدام بأمان.
- الحل المعتمد: تصدير **WordPress XML (WXR)** من الموقع القديم ورفعه عبر `/admin/legacy-import`. تبدأ المواد كمسودات، مع تاريخ النشر الأصلي ورابطها القديم، دون نسبة الكاتب من اسم حساب WordPress.

## آلية الاستيراد المنفذة

1. الدخول إلى لوحة WordPress القديمة واختيار **أدوات ← تصدير**؛ اختيار «كل المحتوى» أو المقالات ثم تنزيل ملف XML. قد يلزم تقسيم الملف إذا تجاوز 20MB.
2. الدخول إلى لوحة ساس الجديدة، قسم **ترحيل أرشيف ساس** في `/admin/legacy-import`.
3. رفع WXR؛ يُقرأ الملف داخل المتصفح، وتُعرض التحليلات أولًا ثم مقالات الرأي ثم البودكاست. غير المصنف يؤجل افتراضيًا.
4. تعديل نوع كل مادة واختيار ما ينبغي نقله. النقل على دفعات بحد أقصى **10 مواد**.
5. تُنشأ مسودات فقط بمعرّفات `sas-legacy-wp-<id>` ثابتة ويُحفظ المصدر القديم كرابط منفصل من نوع `reference`، مع معلومات حساب الناشر لأغراض التدقيق **لا باعتبارها مؤلفًا**.
6. مراجعة متن المادة كاملًا واسم الكاتب ومرفقاتها ومصدرها وتاريخها، وتحرير الأخطاء الناتجة من تحويل HTML إلى فقرات، قبل النشر اليدوي.
7. بعد موافقة تحريرية على المادة، يمكن إنشاء تحويلات 301 لروابطها السابقة عند نقل النطاق؛ لا نفعل ذلك ما دامت المواد القديمة تُخدم من مصدرها.

## موانع النشر

- **لا تستورد** مادة بعنوان ومقتطف فقط إذا كان متنها غير كامل.
- **لا تنسب** المقال إلى حساب WordPress الذي رفعه دون التحقق من سطر «بقلم».
- **لا تعيد نشر** صور أو ملفات وسائط غير واضحة الحقوق أو غير متاحة للتحقق.
- **لا تنشئ تحويلات 301** قبل وجود الصفحة البديلة والتحقق من صحتها.
- **لا تُدخل أي تعديل في `main`** قبل نجاح الفحوص وأمر المستخدم الصريح؛ هذه الحزمة مبنية فوق سلسلة تطوير غير مدمجة.

## نقاط قبول المرحلة

- ينجح فحص `node --experimental-strip-types --test scripts/check-legacy-wordpress-migration.mjs` وفحص `npm run typecheck` و`npm run build`.
- يُرفع WXR حقيقي في البيئة المحلية مع حساب مدير نشط، ويُختبر نقل تحليل واحد ثم تكراره، ثم نقل مقال وبودكاست.
- النتائج تظهر كمسودات داخل `/admin/content`، ويرتبط كل سجل برابطه القديم؛ لا يظهر في الموقع العام إلا بعد قرار نشر منفصل.
- فحص إعلامي/تحريري قبل اعتماد المواد.

**المرحلة التقنية نُفذت؛ ترحيل النصوص نفسه معلق على الحصول على المصدر الكامل WXR أو إصلاح واجهة WordPress.**
