## 1. التحول التحريري المعتمد

قرر المستخدم تحويل ساس **من موقع أخبار آنية ينشر أخبارًا بصورة مستمرة** إلى **منصة للمعرفة السياسية**، تتخذ الأخبار والمواقف والبيانات مادة خام لتنظيم المعلومات وتفسير التطورات وإنتاج معرفة سياسية قابلة للاسترجاع. الشعار الرسمي في الواجهة: **«مِن الخَبر، إِلى المعرِفَة»**.

**الأقسام العامة الأربعة والترتيب المعتمد:**
1. **الإحاطة اليومية** — المنتج المحوري: `/briefings`.
2. **التحليل والدراسات** — يشمل التحليل والرأي والدراسات وأوراق السياسات: `/insights`.
3. **المعرفة البصرية** — إنفوجرافيك ومواد تفسيرية مرئية مرتبطة بالسياق السياسي: `/visual-knowledge`.
4. **الفيديو والبرامج** — مقاطع مختصين، حوارات، فيديو، بودكاست وبرامج: `/programs`.

**تغييرات المسارات:** `/news` يحيل علنًا إلى `/briefings`، و`/media` إلى `/programs`. تبقى `/analysis` و`/research` موجودتين لضمان استمرارية الروابط القديمة. روابط المواد المنشورة مباشرة من `/content/[slug]` لا تُلغى. **محرر الأخبار وجدولها محفوظان داخليًا** للرصد وتغذية الإحاطات، لكنهما ليسا قسمًا عامًا مطلوبًا تحديثه كل ساعة. لم نغيّر مخطط قاعدة البيانات لتنفيذ التقسيم، بل ربطنا مسارات المنتجات الجديدة بالتقسيمات الحالية وفرزنا صيغ الوسائط حسب `format`.

**أولويات تحريرية مقترحة وليست التزامات نشر نهائية:** إحاطة الساعة 20:00 بتوقيت اليمن، مبدئيًا خمسة أيام أسبوعيًا بعد اختبار القدرة؛ مادتان معرفيتان بصريتان وفيديو قصير أسبوعيًا إن سمحت الموارد؛ التحليل والدراسات وفق الجاهزية. الإحاطة ليست قائمة أخبار فقط: «ماذا حدث؟ ما الذي تغيّر؟ وما الذي يستحق المتابعة؟» مع مصادر أصلية، وتفريق الوقائع والادعاءات والمواقف والتحليل. لا توسّع المحتويات بلا قرار مبني على القدرة التشغيلية.

**الجمهور المرجح:** القارئ السياسي الجاد والباحث والصحفي والفاعل السياسي، مع قابلية الاستفادة للقارئ العام المثقف. **الاتجاه طويل الأمد:** ذاكرة سياسية مترابطة للمصادر والجهات والأحداث والقضايا، لا موقع أخبار تقليدي؛ قاعدة المعرفة المتقدمة مؤجلة في المنتج العام الحالي.

## 2. البنية الحالية

- **Frontend:** Next.js 16.4.5 App Router، React، TypeScript، Tailwind، واجهة عربية RTL.
- **Code:** GitHub `dinobahkam-wq/SAS_Platform`، و`main` مصدر الحقيقة بعد دمج PR #53 و#54.
- **Database / media:** Supabase المشروع `budsfbyrdpjkobqstpyr`؛ أوعية ووسائط خبرية موجودة؛ احفظ بيانات الاتصال في `.env.local` غير المتتبّع فقط. لا تعرض أسرار Supabase.
- **Deployment:** Vercel مشروع `sas-platform`؛ سجل GitHub الأخير أظهر عائق build rate limit لحساب Vercel. **نجاح الدمج لا يساوي نشرًا إنتاجيًا.**
- **Windows paths:** اللابتوب الشخصي `C:\SAS-PLATFORM-DEV`، كمبيوتر المحل `D:\SAS-PLATFORM-DEV`. على الجهازين يجب التحقق من `git status` قبل التبديل أو السحب. لا توجد للمساعد صلاحية مباشرة لتشغيل أوامر على جهاز المستخدم.
- **الهوية:** شعار ساس الملوّن من المستودع، ألوان تركوازية ورمادية، Threads WebGL2 كخلفية موقع متحركة خفيفة على الويب، تخفيف على الهاتف وتقليل الحركة، دعم الوضع الفاتح/الداكن، تبديل المظهر في الهيدر قرب دخول الإدارة. واجهة عربية فقط بقدر الممكن، وأرقام لاتينية `0–9`.
- **الخطوط:** Tajarib Taweel للعناوين الملائمة، Thmanyah Sans للمتن، وثمانية Display في بعض استعمالات السلوغن السابقة؛ اتبع الكود/الهوية المعتمدة بدل تعميم خط جديد. لا ترفع ملفات خطوط أو تدّعي ترخيصًا جديدًا دون التحقق.
- **الصور:** لا تستخدم صورًا مولدة بالذكاء الاصطناعي بوصفها صورًا توثيقية لليمن. صورة المكلا الحقيقية ما تزال أصلًا في `public/sas-mukalla-hero.webp` لكنها لم تعد خلفية الرئيسية. احتفظ بحقوق المصور وسجلها، واحرص على تراخيص الاستخدام.

## 5. سير العمل الآمن والمحترف

1. عند كل جلسة، اقرأ هذا التسليم ورأس `CURRENT_STATE.md`، وافحص GitHub (`main`, PRs, commits, branches) بدل الاعتماد على SHA تاريخي.
2. ابدأ الفروع الجديدة من `main` مباشرة؛ لا تبنِ حزمًا جديدة على فروع تجارب منتهية.
3. اكتب نطاقًا صغيرًا لكل حزمة، ثم نفذ عبر GitHub، واطلب اختبارها محليًا قبل الدمج. تحدث وثائق الحالة والتغيير مع الحزمة.
4. لا تعدل Supabase الإنتاجي أو تغيّر RLS أو مخطط الجداول إلا وفق مراجعة Migration وصلاحيات وآثار. التغييرات في المحتوى الإنتاجي تتطلب تحديدًا دقيقًا وحماية من الحذف غير المقصود.
5. افحص `npm run typecheck`, `npm run build`, `npm run dev`, والروابط/الهواتف/الوضع الليلي و404 وأي اختبارات تخص المنتج. لا تقل «نجح» دون مخرجات.
6. في أوامر PowerShell: **أعط المستخدم كتلة واحدة مرتبة قابلة للنسخ**، مع بدء `cd C:\SAS-PLATFORM-DEV` على اللابتوب أو `cd D:\SAS-PLATFORM-DEV` على كمبيوتر المحل حسب الجهاز المصرّح به. لا تجعل `elseif` أو `else` في دفعة منفصلة؛ ولا تُشغِّل Git خارج المجلد.
7. لا تستخدم `reset --hard` أو `git clean` أو حذف stash/ملفات/فروع قبل فحص `git status` واستيعاب التعديلات. راقب ملفات `next-env.d.ts`, `.env.local` والأصول غير المتتبعة.
8. بعد الاختبار، افحص قابلية الدمج وفرق الملفات ورأس الفرع، ثم ادمج إلى `main` عندما يطلب المستخدم. راقب Vercel منفصلًا؛ حالة `BLOCKED` أو build rate limit لا تثبت مشكلة TypeScript.
9. لا تطلب من المستخدم إعادة تفاصيل متوفرة في السياق والمستودع؛ نفّذ عبر الإضافات المتاحة بدل تكرار تعليمات يدوية ما دام ذلك آمنًا وممكنًا.

## 6. تفضيلات المستخدم في التعاون

- تعامل كشريك استشاري ناقد، لا كمؤيد لكل فكرة؛ **ناقش الاعتراضات والتكاليف والبدائل وقل النتيجة بوضوح**.
- العربية المهنية المختصرة المركّزة، لا مدح مفرط ولا استطراد ولا نصوص إنجليزية في الواجهة العامة.
- يحب المبادرة بالتنفيذ الفعلي في GitHub/Supabase حين يطلبها، لا الاكتفاء بتوصيات نظرية؛ لكن افصل المعتمد عن المقترح، والمكتمل عن غير المختبر.
- **أوامر الطرفية دائمًا في كتلة PowerShell واحدة جاهزة للنسخ**، وبالتسلسل الصحيح والمسار الصحيح، إلا إذا استدعت نافذتان منفصلتان شرحًا واضحًا.
- عند استكشاف فشل: **اعثر على السبب الجذري وفحص الدورة كلها** (DB → query → route → UI → build/HTTP) بدل معالجة العرض الظاهر فقط.
- يحب مراجعة النتائج بالصور والشاشات بعد كل حزمة، وتحسين التصميم عبر النقد المباشر والتكرار البصري.
- تصميم مؤسسي حديث وبسيط، خطوط عربية مدروسة، ألوان الشعار التركوازي والرمادي، اتساق الوضع الليلي، وثبات الأداء والاستجابة للهاتف.
- الأخبار والسياسة: أولوية للبيانات الرسمية الأصلية؛ عند تحليل مواقف الدول تُقارن الصياغات الحرفية وتصنّف (إدانة صريحة/ضمنية، حياد، تهدئة، تحميل مسؤولية)، مع عدم تحويل الادعاء إلى حقيقة.
- يفضل الحفاظ على الموارد المحدودة وفريق صغير، والاستثمار في منتجات دائمة القيمة لا كثافة نشر عالية.

- لا تعِد بعمل لاحق غير منفذ؛ قدم التقدم المحقق والوضع القائم والاختبار المطلوب.

## 7. أول خطوة في المرحلة المقبلة

**الأولوية المعمارية للإحاطة:** توثيق المصادر، المقارنة مع الإصدارات السابقة، طبقة «ما الذي تغيّر؟»، فصل الادعاءات والمواقف من الوقائع، إتاحة روابط دائمة للأعداد والتصحيحات، ومساعدة محرر لا مساعد عام. لا تفترض تفعيل صيغة 5 أيام أو الساعة 20:00 رسميًا قبل اعتمادها تشغيليًا.
