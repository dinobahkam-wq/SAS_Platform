## 2. المرحلة المكتملة: استوديو الصور الإخبارية

الوثيقة المرجعية: [استكمال استوديو الصور الإخبارية](../news-studio-completion-2026-11-12.md).

المخرجات المدمجة في التكامل:
- محرك Canvas للرسم النهائي وتصدير PNG.
- خيارات المقاسات المسبقة والمخصصة ولوحات الألوان والقوالب والإعدادات المحفوظة.
- خيارات الخطوط والصورة والهوامش.
- استيراد JSON وMarkdown وTXT.
- حد موحد للموجز 250 كلمة وتقسيم المحتوى على صفحات.
- طبقة SVG للتحديد والتحريك والتحجيم للعناصر المدعومة، مع الحفاظ على نسبة أبعاد الصورة وفصل أدوات التفاعل عن PNG.

**التحقق المحلي المبلغ عنه من المستخدم:** نجاح `npm run typecheck` و`npm run build` على رأس PR #28 `2fcd4ad9bdcfcde240f4755e00c59f0c6edff22c`، ونجاح اختبار الاستيراد والتحريك والتحجيم وتصدير PNG. لا يُنسب هذا الاختبار إلى نشر Vercel.

**غير مثبت ضمن قبول هذه الحزمة:** Layers كاملة، Undo/Redo، المساطر والأدلة، القفل والنسخ والحذف، والتحرير النصي المباشر المتقدم. راجع وثيقة الاستوديو قبل إعادة فتح هذا النطاق.

## 3. المرحلة الجديدة: الإحاطة اليومية V1

الوثيقة المرجعية: [مواصفات الإحاطة اليومية V1](../daily-briefing-v1.md).

الهدف: منتج يومي تحريري وتحليلي يركز على اليمن، يجمع قراءة تفسيرية رئيسية بين 400 و650 كلمة مع سجل أوسع للتطورات ومصادر موثقة ومنهجية وحدود تغطية معلنة وأرشيف للأعداد.

المعتمد في اتجاه المنتج:
- الفصل بين FACT وPOSITION وCLAIM وANALYSIS.
- إظهار نافذة التغطية ووقت آخر تحقق.
- الاختيار وفق التأثير والجدة والانتشار والتوثيق والاستمرارية.
- مسار العدد: مسودة ← مراجعة ← اعتماد ← نشر.
- الأرشيف والإحاطات الاستثنائية عند الأحداث الكبرى.
- واجهة ويب متجاوبة؛ PDF والخرائط مؤجلان عن V1.

### الوضع البرمجي الحالي للقسم

- لا يوجد في فرع التكامل مسار `src/app/briefings/page.tsx`.
- لا يوجد مسار `src/app/admin/briefings/page.tsx`.
- لا توجد Migrations خاصة بالإحاطة ضمن `supabase/migrations/`.
- مخطط SAS_Platform الحالي يستخدم `public.content_items` و`public.content_sources` و`public.content_source_links`، وقيمة section الحالية هي `news` و`analysis` و`research` و`media`.
- النموذج القديم موجود في مستودع منفصل `dinobahkam-wq/SAS` على الفرع `feature/daily-briefing-v1`. يُستخدم مرجعًا وظيفيًا فقط؛ لا تنقل SQL أو RPCs أو أسماء الجداول منه مباشرة.

### أول حزمة مطلوبة

1. تدقيق صفحات الإحاطة القديمة ومحررها وSQL/RPCs المرتبطة بها.
2. فحص مخطط SAS_Platform الحالي وRLS وسجل migrations.
3. حسم وحدة التطور: مادة منشورة موجودة أم سجل تطور مستقل مرتبط بمصدر/حدث/قضية.
4. إعداد تصميم بيانات وحالات وصلاحيات قبل أي Migration.
5. بعد اعتماد التصميم، تنفيذ لوحة التحرير ثم دورة المراجعة والاعتماد والنشر ثم الواجهة العامة والأرشيف.

**لا تُطبق أي Migration على Supabase البعيد قبل عرضها ومراجعتها والموافقة عليها.**
