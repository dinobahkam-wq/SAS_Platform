## ما نُفذ فعليًا في فرع الواجهة

- صفحات: `/`، `/news`، `/analysis`، `/research`، `/media`، `/content/[slug]`.
- جلب المواد المنشورة من Supabase فقط عبر `src/lib/public-content.ts`، مع بقاء RLS حد الأمان الفعلي.
- عرض الصور الرئيسية والبيانات والمصادر والمؤلفين وقوالب الخبر والتحليل والدراسة.
- حزمة #7: تصحيح وراثة الخط الافتراضي إلى Thmanyah Sans، وضبط وزن العناوين، والتمييز بين عطل القراءة والنتائج الفارغة، وإجبار صفحات البيانات العامة على العرض وقت الطلب لتجنب فشل توليد الصفحات مسبقًا عند استخدام `cookies()`.

## نتائج الاختبار المعروفة — لا تُعمّمها على رؤوس جديدة

- المستخدم أبلغ أن `npm run typecheck` نجح على نسخة أولية من PR #7.
- فشل `npm run build` حينها عند توليد `/analysis` بسبب `DYNAMIC_SERVER_USAGE` المرتبط بـ `cookies()`. عولج **في الكود على GitHub** بإضافة `dynamic = "force-dynamic"` لصفحات البيانات؛ **لا توجد نتيجة بناء محلي جديدة مثبتة بعد هذا الإصلاح ضمن السياق المعتمد**.
- تجربة `npm run dev` الأولى كشفت فقد متغيرات Supabase؛ الصورة اللاحقة بتاريخ 10 نوفمبر أظهرت الصفحة الرئيسية الفعلية مع حالات خلو، لكن لا توجد شهادة منشورة لنتيجة البناء الإنتاجي بعد ضبط البيئة.
- المعاينة البصرية العامة: عنوان تجاريب العريض ظاهر، أقسام أربعة تعرض حالات خلو، والرأس والتذييل يعرضان شعار ساس. الملاحظات: حالات الخلو طويلة؛ ضرورة اختبار الرأس على الهاتف، وشعار الرأس يبدو صغيرًا نسبيًا.
- لم يثبت اختبار حالات المحتوى المنشور والمسودات والأرشيف مباشرة من متصفح مجهول.
