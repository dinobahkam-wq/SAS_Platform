# Package 02 — دليل إدخال المسودات وربط الصور

**التاريخ:** 11 نوفمبر 2026  
**مصدر العمل:** ملف خاص مرفوع من المستخدم يحتوي 38 مادة، أُعدّت منه 20 مسودة سياسية.  
**الوضع حتى كتابة الدليل:** تم إنشاء ملفات تنفيذ خاصة خارج GitHub؛ **لم تُكتب المسودات بعد إلى قاعدة Supabase**.

## قاعدة البيانات المستهدفة

- Supabase project: `budsfbyrdpjkobqstpyr` (`SAS_Platform`)، وليس مشروع `SAS` القديم.
- جدول المقالات: `public.content_items`.
- جدول مراجع الأرشيف: `public.content_sources` مرتبط بـ`public.content_source_links`.
- الصور: Storage bucket `sas-public-media` وجدول `public.media_assets`.
- العلاقة بين الصورة والمقال: `content_items.cover_asset_id = media_assets.id`.

## إدخال مواد الأخبار

أُعدَّ ملف SQL خاص بالمستخدم `sas_import_20_drafts.sql` داخل مساحة ملفات المحادثة؛ لا ترفع الملف إلى مستودع GitHub العام، فهو يضم نصوص المقالات كاملة. يُشغّل من SQL Editor في Supabase بعد مراجعة الملف، وليس من واجهة WordPress.

- 20 سجلًا من قسم `news` مع `status='draft'` و`published_at=NULL` و`cover_asset_id=NULL`.
- نص المادة محفوظ كـJSONB متوافق مع `body.blocks`.
- سجل مصدر منفصل لكل مادة يحتفظ بالرابط القديم ورقم WordPress والتاريخ المحلي الأصلي **من دون افتراض صحة المنطقة الزمنية**.
- الملف مُحصّن ضد إعادة إدخال سجل له المصدر URL نفسه أو slug موجود مسبقًا، وينفذ الخطوات في معاملة واحدة.
- المصادر السياسية الرسمية تحتاج تحققًا مستقلًا قبل النشر؛ أرشيف ساس القديم ليس بديلًا عن النص الأصلي للقرار أو البيان.

## رفع الصور يدويًا

**المسار المفضل من واجهة ساس نفسها:** صفحة `/admin/media` ترفع إلى Storage **وتنشئ سجل `media_assets` تلقائيًا**، وبعد ذلك تعرض صفحة `/admin/content/[id]` اختيار صورة الغلاف. يلزم تسجيل دخول إداري.

**عند الرفع مباشرة من Supabase Dashboard:** ارفع إلى `Storage > sas-public-media > legacy`، بأسماء الملفات `5816.webp` مثلًا (مع استعمال الامتداد الفعلي). رفع Storage وحده **لا ينشئ** سجل `media_assets`. بعد اكتمال الرفع يجب أن ينشئ المسؤول سجل الوسائط لكل كائن ويطابق مصدر المنشور القديم إلى سجل المحتوى، ثم يحدث `cover_asset_id`، مع التحقق من الأبعاد وحقوق الملكية ووصف الصورة.

- كشف مطابقة خاص `sas_image_linking_manifest.csv` متاح للمستخدم من ملفات المحادثة.
- لا تحمّل أي صور من WordPress تلقائيًا.
- لا تنقل مواد `review` أو `exclude` إلى الموقع السياسي تلقائيًا.

## شروط التحقق بعد الإدخال

1. عدّ المواد المرتبطة بمصادر `https://www.sas-media.net/post/%` وعدّ المسودات.
2. التأكد أن `published_at IS NULL` وأن `cover_asset_id IS NULL` حتى إجراء ربط الصور.
3. التأكد من عدم تكرار روابط المصدر وأن عدد روابط المقالات متوقع.
4. فتح `/admin/content` ومراجعة النصوص والتواريخ وعناوين المصادر.
5. بعد تحميل الصور وربطها، فحص صورة لكل خبر ووجود أصل واحد مقابل كل منشور.
6. لا تنشر أي مادة دون اعتماد تحريري وبحثي.

## ملاحظة تشغيلية

قاعدة الإنتاج لم تشهد أي كتابة في مرحلة إعداد SQL الخاصة بالمستخدم؛ عدم تنفيذ SQL لا يعني أن المسودات ظاهرة في لوحة الإدارة. تجنّب صياغة تقارير تؤكد الاستيراد قبل إجراء تحقق SQL مباشر.
