# بروتوكول التطوير والتوثيق — GitHub مصدر الحقيقة

**آخر تحديث:** 11 نوفمبر 2026.

## القاعدة التنظيمية

- `dinobahkam-wq/SAS_Platform` هو المستودع الرئيسي.
- تُنفذ الحزم بواسطة موصل GitHub في فروع مستقلة وتُفتح PRs للمراجعة؛ لا تطوير مباشر على `main`.
- Supabase `budsfbyrdpjkobqstpyr` هدف التشغيل والتحقق، وليس مصدرًا بديلاً غير موثق لتعديلات المخطط؛ كل تغيير مخطط مقصود يمثل في migration مُراجَعة.
- بعد رفع الحزمة إلى GitHub يُطابق الفرع في Worktree محلي ثم يُختبر.
- لا ادعاء بنجاح اختبارات غير مُجراة، ولا دمج أو نشر إنتاجي إلا بإذن منفصل.

## دورة حزمة التطوير

1. **استعادة السياق:** اقرأ `AGENTS.md` وهذا المجلد؛ افحص الحالة الحية لـ PRs والـ SHAs.
2. **تعريف الحزمة:** الهدف، النطاق، الملفات، أثر البيانات والأمان، معايير قبول قابلة للفحص.
3. **تنفيذ:** أنشئ فرعًا من آخر رأس تطوير معتمد (ليس بالضرورة `main` حين توجد PRs مكدسة)، وPR مستقلًا.
4. **توثيق في نفس الفرع:** حدّث `CHANGELOG.md` و`CURRENT_STATE.md`، وسجّل الاختبارات المتحققة وغير المتحققة بصورة صريحة. احرص على عدم نسخ تاريخ قديم فوق المستند.
5. **مزامنة محلية:** احفظ التعديلات المحلية؛ استعمل `git fetch origin`، و`git pull --ff-only` في Worktree المخصص فقط. لا `reset --hard` أو `rebase` عشوائيًا.
6. **اختبارات:** `npm run typecheck`، `npm run build`، `npm run dev`، اختبارات الصفحات والروابط وRTL والهواتف والصلاحيات حسب نطاق الحزمة.
7. **مراجعة وإصلاح:** أرسل نتائج اختبار Windows ولقطات الشاشة؛ أصلح على GitHub، وأعد المطابقة.
8. **اعتماد:** لا دمج ولا إطلاق قبل التحقق المحلي، ومراجعة الأمان، وموافقة المستخدم.

## Windows — مسار الاختبار الحالي

- النسخة الأصلية: `C:\SAS-PLATFORM-DEV`، وبها تعديلات محلية تاريخية لا يجب إزالتها.
- Worktree: `C:\SAS-PLATFORM-DEV-REVIEW`، أنشئ في جلسة سابقة على فرع مراجعة يتتبع `origin/fix/public-editorial-stability-v1`.
- قبل `pull`: تحقق من `git status --short` في Worktree. إذا ظهرت تعديلات محلية، لا تتجاوزها.
- `npm install --no-audit --no-fund` عند الحاجة. لا ترفع `node_modules` أو `.env.local`.
- عند فقد إعدادات Supabase محليًا، يمكن استخدام ربط Vercel الصحيح لجلب **development** env إلى `.env.local` من `sas-platform`؛ لا تعرض القيم ولا تنسخ service-role keys.
- لا تربط النسخة المحلية بمشروع Supabase القديم المسمى `SAS`.

## توثيق التغييرات وتعارضها

- اكتب كل حدث بوسم: **مطبق على GitHub**، **مجرب محليًا**، **مدمج**، **منشور**، أو **مخطط**. ليست مترادفات.
- عند تغيير فرع التطوير، حدّث الرابط والـ SHA وتاريخ التحقق.
- لا تكتب في السجل نتيجة اختبار إلا إذا ظهرت في مخرجات أو في CI حقيقي على رأس الفرع نفسه.
- قبل محادثة جديدة، افحص `main`؛ إن كانت وثائق الذاكرة لم تُدمج بعد فاقرأ فرع `docs/project-memory-v1`، ثم انتقل إلى رأس PR التطويري لتفاصيل الكود.

## ما لا تفعله

لا تُعد تنظيم تاريخ الفروع أو دمج السلسلة المعلقة من تلقاء نفسك؛ لا تكتب مفاتيح، بيانات اعتماد، محتوى خصوصيًا، أو نصوص مراسلات في الذاكرة التنفيذية. لا تفترض أن المكوّن الإضافي يستطيع تعديل ملفات Windows مباشرة؛ المطابقة المحلية خطوة مستقلة ينفذها المستخدم أو وكيل متصل بجهازه.
