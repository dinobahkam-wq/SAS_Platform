## دورة حزمة التطوير

1. **استعادة السياق:** اقرأ `AGENTS.md` وهذا المجلد؛ افحص الحالة الحية لـ PRs والـ SHAs.
2. **تعريف الحزمة:** الهدف، النطاق، الملفات، أثر البيانات والأمان، معايير قبول قابلة للفحص.
3. **تنفيذ:** أنشئ فرعًا من آخر رأس تطوير معتمد (ليس بالضرورة `main` حين توجد PRs مكدسة)، وPR مستقلًا.
4. **توثيق في نفس الفرع:** حدّث `CHANGELOG.md` و`CURRENT_STATE.md`، وسجّل الاختبارات المتحققة وغير المتحققة بصورة صريحة. احرص على عدم نسخ تاريخ قديم فوق المستند.
5. **مزامنة محلية:** احفظ التعديلات المحلية؛ استعمل `git fetch origin`، و`git pull --ff-only` في Worktree المخصص فقط. لا `reset --hard` أو `rebase` عشوائيًا.
6. **اختبارات:** `npm run typecheck`، `npm run build`، `npm run dev`، اختبارات الصفحات والروابط وRTL والهواتف والصلاحيات حسب نطاق الحزمة.
7. **مراجعة وإصلاح:** أرسل نتائج اختبار Windows ولقطات الشاشة؛ أصلح على GitHub، وأعد المطابقة.
8. **اعتماد:** لا دمج ولا إطلاق قبل التحقق المحلي، ومراجعة الأمان، وموافقة المستخدم.

## Windows — مسار الاختبار الحالي

- النسخة الأصلية: `C:\SAS-PLATFORM-DEV`، وبها تعديلات محلية تاريخية لا يجب إزالتها.

- قبل `pull`: تحقق من `git status --short` في Worktree. إذا ظهرت تعديلات محلية، لا تتجاوزها.
- `npm install --no-audit --no-fund` عند الحاجة. لا ترفع `node_modules` أو `.env.local`.
- عند فقد إعدادات Supabase محليًا، يمكن استخدام ربط Vercel الصحيح لجلب **development** env إلى `.env.local` من `sas-platform`؛ لا تعرض القيم ولا تنسخ service-role keys.
- لا تربط النسخة المحلية بمشروع Supabase القديم المسمى `SAS`.
