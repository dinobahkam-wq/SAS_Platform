# منصة ساس — الذاكرة التنفيذية الرسمية

**الغرض:** مرجع معرفة مؤسسي مستمر للمشروع عبر المحادثات والوكلاء.  
**المصدر المعتمد:** [dinobahkam-wq/SAS_Platform](https://github.com/dinobahkam-wq/SAS_Platform).  
**تاريخ إنشاء المسار:** 11 نوفمبر 2026.  
**حالة الوثائق:** النسخة الأولى؛ الحقائق القابلة للتغير تحتاج تحققًا مباشرًا من GitHub وSupabase.

> هذه الذاكرة توثّق قرارات المشروع وتنفيذه، لكنها لا تحل محل التحقق الآني من حالة المستودع والاختبارات. **وجود ملف في فرع مفتوح لا يعني دمجه في main أو نشره.**

## ترتيب القراءة الإلزامي للمحادثة الجديدة

1. [الحالة التنفيذية الحالية](CURRENT_STATE.md) — المرجع التنفيذي المختصر: الفروع، الاختبارات، المشكلات والمهام التالية.
2. [القرارات والهوية والنطاق](DECISIONS.md) — القرارات الملزمة، وما أُجِّل، وما يحتاج اعتمادًا.
3. [بروتوكول العمل والمزامنة](WORKFLOW.md) — طريقة التطوير على GitHub ثم المطابقة والاختبار المحلي.
4. [سجل الحزم والتغييرات](CHANGELOG.md) — ماذا نُفذ، وأين، وكيف تحققنا منه.
5. [دليل ملفات التنفيذ](REFERENCES.md) — وثائق المخطط والهوية وقوالب الصفحات وروابط PRs.

## طريقة استخدام هذا المسار

- تبدأ أي محادثة جديدة بقراءة الملفات المذكورة **مباشرة من GitHub** عبر الموصل، ثم فحص PRs والـ Commits الحالية.
- عند اختلاف مستند وصورة أو وصف شفهي عن GitHub، افصل بين قرار التصميم والموجود فعليًا في الكود؛ لا تُعد كتابة التاريخ ولا تُخفِ التعارض.
- كل حزمة جديدة تحدث `CURRENT_STATE.md` و`CHANGELOG.md` في نفس فرع الحزمة، وتضيف قرارًا إلى `DECISIONS.md` فقط إن اتُخذ قرار جديد.
- اعتمد روابط دائمة إلى commits/PRs، وأضف تاريخ وتاريخ تحقق لكل معلومة متغيرة.
- لا تُنشئ بيانات تجريبية في قاعدة الإنتاج، ولا تُجري عمليات دمج أو نشر تلقائيًا.

## رسالة انطلاق جاهزة لمحادثة أخرى

> نواصل مشروع منصة ساس. GitHub هو مصدر الحقيقة: `dinobahkam-wq/SAS_Platform`. افتح أولًا `AGENTS.md` ثم كل ملفات `docs/project-memory/` عبر إضافة GitHub، وتحقق من الحالة الراهنة للفروع وطلبات الدمج. لا تفترض أن وثائق `main` تحتوي كود الفروع غير المدمجة. لخّص نقطة الاستئناف ثم نفذ حزمة تطوير مستقلة، وثّقها في المسار نفسه، واطلب مني تشغيلها محليًا قبل اعتمادها.

## مسؤولية التحديث

الوكيل المنفذ مسؤول عن تحديث هذه الملفات مع كل حزمة؛ والمستخدم يعتمد نتائج التجربة المحلية والدمج والنشر. لا يوجد تحديث ذاتي أو تلقائي بين المحادثات دون تنفيذ مهمة موثقة على GitHub.
